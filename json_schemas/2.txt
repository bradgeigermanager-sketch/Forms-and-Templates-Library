一、基础轻量方案（快速落地，适合中小规模数据）

不需要复杂训练，直接调用开源工具管线，10行代码就能集成：

实现流程
提取待检测文本‌：从Schema的所有值字段中提取纯文本（跳过ISO代码、ID这类非文本内容）
调用开源检测工具‌：直接用成熟的预训练模型，不需要自己训练
结果标准化‌：把检测出的语言转换为ISO 639-1代码，自动填充到根节点document_languages字段
人工复核‌：低置信度结果标记出来，人工修正后入库

极简代码示例（Python + cld3）
python
import cld3
# 从我们的Schema中提取所有文本内容
def extract_text_from_schema(schema):
    texts = []
    def traverse(obj):
        if isinstance(obj, dict):
            for k, v in obj.items():
                # 跳过纯标识/代码字段，只检测实际内容文本
                if not k.endswith(('_cn', '_' + '[a-z]{2}', '_note', 'code')) and isinstance(v, (str, list)):
                    if isinstance(v, str): texts.append(v)
                    if isinstance(v, list): texts.extend([i for i in v if isinstance(i, str)])
                traverse(v)
        elif isinstance(obj, list):
            for item in obj: traverse(item)
    traverse(schema)
    return ' '.join(texts)

# 自动检测并填充到Schema的document_languages字段
def auto_detect_language(schema):
    full_text = extract_text_from_schema(schema)
    detected = cld3.get_language(full_text)
    # 置信度大于0.7直接用，否则标记为空待人工复核
    if detected.probability > 0.7:
        schema['document_languages'] = [detected.language]
        return schema, True
    else:
        schema['document_languages'] = []
        return schema, False

二、生产级高准确率方案（适合大规模数据，适配搜索引擎/LLM场景）

针对我们「标准化Schema+提前标注」的设计，优化检测流程，进一步提升准确率：

1. 分层检测策略（解决多语言文档问题）
第一步‌：先检测整文档的主要语言，填充根节点document_languages
第二步‌：针对每个多语言标注字段（比如full_name/full_name_gu），单独检测语言，校验标注是否匹配，错标直接报警
第三步‌：针对小众语言，调用fastText专门识别，提升准确率
2. 结合我们的Schema做校验优化

利用Schema已有的primary_language字段做交叉验证：

如果检测出的文档语言和primary_language标注不一致，自动标记为待复核，避免错标
比如印度用户primary_language标注了gu（古吉拉特语），如果检测结果是hi（印地语），就触发人工检查
3. 增量自动更新
每次更新Schema内容，自动重新检测语言，如果新增了其他语言，自动追加到document_languages数组，不用手动修改
三、结合我们的设计，最终收益
低成本‌：检测结果直接标准化为ISO代码，自动填充到我们设计好的document_languages字段，不需要人工手动填写
省算力‌：自动检测入库后，后续搜索引擎/LLM处理时不用再重复检测，直接读取标注，节省大量计算
准确率高‌：分层检测+Schema已有信息交叉验证，比全量自动检测准确率提升10%以上，小众语言也能准确识别
避免错配‌：从源头就标注好语言，不会出现字符集错配、翻译模型用错的问题，解决你之前提到的“错译麻烦”
